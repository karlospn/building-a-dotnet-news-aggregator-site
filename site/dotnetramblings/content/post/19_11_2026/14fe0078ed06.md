Thread pool starvation does not hang the application, it makes it slow, and it makes it slow in a way that no profiler flags: the CPU is idle, no query is slow, and every individual operation looks fine. What is wrong is that the pool has no thread left to run the next work item, because the previous ones are all blocked waiting for something.
